# 0.5.3: 編集の競合防止と保存データのバックアップ

フォルダー同期中の編集や、複数の管理タブからの更新で新しい保存が消える問題を修正しました。管理画面とポップアップの更新には同じ Web Lock を使い、フォルダーの読み取りからコミットまでを保護します。一括適用・取り込み・復元は、バックグラウンドでライブラリの更新世代も確認します。エディターでは編集開始時のコードを照合し、別の編集が保存済みなら、編集中の内容を残して保存を止めます。

GM の保存は確定済みの値と保存待ちの更新を分けました。同じキーへの保存が連続して失敗しても、最後に確定した値へ戻ります。リスナーにも戻った値を通知します。バックグラウンドの GM 操作とバックアップ・復元は共通のキューで処理します。

ポップアップの URL 判定は実行側と共通です。ワイルドカードのホスト・ポート・フラグメントによる対象一覧の差を修正しました。Android Vivaldi のポップアップは、共通のソースをビルド時にまとめ、引き続きルートの popup.html / popup.js を使う単一の classic script です。

同じ @name / @namespace のファイルを取り込む場合、更新前後のコードを確認してから置き換えます。ID・フォルダー・有効状態・保存データとの関連を保持します。メタデータの一致だけで自動上書きはせず、GM 権限追加や対象範囲の変更は別途確認します。確認中にライブラリが変わった場合は取り込みを止めます。

JSON バックアップに「スクリプトの保存データを含める」を追加しました。初期状態はオフです。オンの場合、GM.setValue / GM_setValue の設定や進捗を、スクリプト ID と正確な HTTP(S) オリジンに結び付けて出力します。JSON 形式 3 は空フォルダーも保存し、従来のコードだけの JSON も読み込めます。フォルダー同期と履歴はコードだけです。自動ダウンロードのバックアップもこの選択に従い、従来どおりスクリプト変更時・ブラウザー起動時に出力します。GM の値が変わるたびの自動ダウンロードは行いません。

復元前に保存値の件数・既存キーの上書き件数・オリジン一覧を確認でき、コードだけの復元も選べます。バックアップにないキーは保持します。復元前の現在の内容は回復用 JSON としてダウンロードします。確認中に保存データが変わったりワーカーが再起動したりした場合は、確認をやり直します。値とライブラリを同じ storage.local.set で保存し、失敗時に一部だけ反映しないようにしています。

実行トークン・通知の一時ルート・承認状態はエクスポートしません。復元で新たな GM 権限を自動付与しません。保存データを復元したスクリプトは古い実行トークンを失効させるため、動作中の Web ページを再読み込みしてください。保存値は個人的な情報を含むことがあるため、バックアップへの収録は利用者が選びます。

配布名は Shieldmonkey-vivaldi.zip、ZIP 直下の manifest.json、読み込み先のフォルダー名・場所はそのままです。
