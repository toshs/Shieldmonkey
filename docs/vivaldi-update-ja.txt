ShieldMonkey 0.5.1 / Android Vivaldi

更新する場合
1. 今 Vivaldi が読み込んでいるフォルダーの名前と場所をそのまま使います。
   名前に古いバージョン番号が入っていても、改名・移動しません。
2. ZIP の中身を、その既存フォルダーへ上書きします。
   manifest.json が既存の manifest.json と同じ場所に来るようにします。
3. 0.4.2 以前から更新する初回だけ、manifest.json と同じ階層に
   _metadata フォルダーがあれば、そのフォルダーだけ削除します。
   ZIP の上書きだけでは、古い _metadata は消えません。
   0.4.3 からは、このフォルダーを生成する静的通信ルールを使わず、
   動的ルールをブラウザー側に登録します。再有効化ごとの削除は不要です。
4. vivaldi://extensions で、今ある ShieldMonkey の「再読み込み」を押します。
   拡張機能を削除したり、別のフォルダーを新しく読み込んだりしません。

初回のみ
ZIP を固定の場所に解凍し、manifest.json のあるフォルダーを
「非パッケージ拡張機能を読み込む」から選びます。
詳細の「ユーザー スクリプトを許可する」を有効にします。
以後はそのフォルダーを使い続けます。

配布 ZIP 名は毎回 Shieldmonkey-vivaldi.zip です。
ZIP の直下に manifest.json があり、バージョン付きの親フォルダーは含みません。
ダウンロードや解凍で「(1)」などが付いても、新しいフォルダーを追加読み込みせず、
中身を元の読み込み先へ上書きしてください。

以前のビルドが生成したフォルダーにより
「Cannot load extension with file or directory name _metadata」と出た場合も、
読み込み先の _metadata だけを削除し、エラー画面の「再読み込み」を押します。
元のフォルダーの名前・場所は変えず、拡張機能自体も削除しません。

0.5.0 の変更
・リンクからの .user.js インストールと URL 更新は廃止しました。
  ファイルの取り込み・貼り付け・エディター・ローカルフォルダー同期を使います。
・新規スクリプト、GM 権限の追加、対象サイト変更には確認が必要です。
  フォルダーや履歴からの未承認の変更は、無効状態で確認を待ちます。
・Chromium で同一ページの個別実行分離の上限を超えた場合、超過分は実行しません。
・GM 保存値は引き継ぎます。サイトの localStorage へのキャッシュは廃止しました。
・CORS ヘッダー変更ルールを削除し、画面からの遷移保護ルールだけを残しました。

0.5.1 の修正
・設定・ヘルプの最下部が下部タブバーに隠れる表示を修正しました。
・保存済みのフォルダー接続と永続アクセス権を復帰させます。ブラウザーが一時許可のみの場合は、再接続ボタンで同じフォルダーを許可できます。
